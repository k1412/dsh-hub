# Agent Note: DSH Hub 控制平面与出站节点连接器

Status: implemented

[English](2026-08-16-dsh-hub-control-plane.md) | 中文

## Problem

一个操作者可以在多台电脑上运行 DSH，并使用各机器上的本地 Web 和桌面端界面。每个界面原本只能访问本地 Runtime，因此不能在一个经过认证的页面中列出全部节点、远程继续工作，或管理精确的插件和快照状态。公开每个本地 Web 监听器会增加面向互联网的源站数量，并让 Web API 成为远程控制能力的上限。在中心服务内运行 DSH 会产生第二套执行模型，而完整镜像节点数据会形成第二事实源和无边界缓存。

控制平面必须让每个节点继续作为其 DSH Runtime 和数据的权威来源，与全部本地客户端共存，让已注册的 Hub 拥有 DSH Context 与 Node Agent 操作系统账户的完整权限，并且不要求节点开放入站监听器。

## Decision

DSH Hub 是单用户控制平面，不是 DSH Runtime。它负责认证操作者、注册节点、路由带版本的能力命令、索引展示节点集合所需的元数据、提供精确插件与快照操作，并记录仅追加的哈希链审计日志。它不会创建 DSH `Context`、运行模型或工具，也不会加载节点的 DSH 插件。同时承载 Hub 的机器如需执行任务，也通过与其他机器相同的节点路径加入。

每台受控机器安装两个协作组件。Hub Connector 是加载到现有 DSH Composition 中的 Cordis 插件；该 Composition 提供与传输无关的 Host `ApiProxy` Service，Connector 通过该 Service 公开会话、设置和 Runtime 能力。Node Agent 是运行在 DSH 所属操作系统账户下的独立进程，负责节点身份、持久化 WSS 交付、本地 IPC、插件制品激活、快照、受大小限制的文件操作，以及由已审计命令表示的 PTY 流。

Connector 不依赖 Web 传输，也不代理其 HTTP、SSE 或浏览器 WebSocket 接口。标准 Web Profile 已提供 Host Gateway；其他 Composition 会显式提供它。当本地 Web、桌面客户端与 Hub Connector 连接同一个 Runtime 时，三者操作同一个实时会话所有者。资源身份为 `{nodeId, runtimeId, resourceId}`。本地显示状态留在本地；会话消息、队列状态、取消、批准和问题以 DSH 为权威，并通过各界面的正常投影显示。

## Authority and isolation

Hub 是已注册 Node Agent 接受的唯一应用级命令权威。经过正确认证和签名的命令不再要求节点端二次批准。Connector 操作继承 DSH Context 的全部权限；管理器、文件系统、进程和 PTY 操作继承 Node Agent 所在操作系统账户的全部权限。安装过程不会静默提权，而选择特权账户运行始终是显式部署决定。

节点建立一条出站 WSS 连接。Node Agent 与 Connector 通过有帧长度限制、HMAC 认证且密钥仅所有者可读的本地 IPC 通信。两者都不开放可从互联网访问的监听器。人类流量与机器流量可以共用一个边缘主机名，但人类请求必须具备已验证的 Cloudflare Access JWT 并通过同源变更检查；机器请求必须同时具备每节点 Cloudflare Service Token 和绑定到已注册节点身份的 Ed25519 证明。

Hub 服务端依据当前 JWKS 验证 Access JWT 的签发者、受众、签名、类型、时间边界和精确操作者身份。它还要求私有反向代理边界提供高熵源站密钥。因此 Access 层认证是必要条件而非唯一条件，直接抵达源站地址或端口也不能绕过应用认证。

## Protocol and recovery

Hub 与 Node Agent 交换签名信封，其中包含协议版本、节点与可选 Runtime 身份、启动身份、连接代次、消息身份、单向序号、累计确认、时间边界、载荷哈希和载荷。认证会分配新的连接代次，并协商包含语义版本和 Schema 哈希的精确能力描述符。

双方都在确认前持久化命令和结果。重连时交换确认位置，拒绝过时代次和重复消息身份，重放未确认的持久记录，再校准 Runtime 实例、能力、未完成命令和流基线。变更命令必须提供幂等键或显式校准过程。副作用发生但结果未确认时返回 `outcome-unknown`，不会盲目重新执行。Hub 会在浏览器显式确认结果后删除已完成命令正文，并定期对无人领取的终止记录应用有界清理窗口。

浏览器合约由 Hub 在 `/hub/v1` 命名空间内拥有。JSON REST 承载有界请求和变更，可恢复 SSE 通道承载可重建的控制事件，专用同源 WebSocket 转发交互式 PTY 帧。Hub 可以复用 MIT 许可的上游类型或实现，但不承诺未经修改的上游 Web 客户端可以连接，而且上游 Web API 不是 Hub 到节点的协议。

## Storage and fleet operations

参考部署使用 WAL 模式 SQLite 和内容寻址目录。SQLite 保存节点身份、Runtime 与能力元数据、会话索引、命令交付状态和审计记录。对象目录只接受操作者显式导入的不可变制品，普通节点流程不会填充该目录。Node Agent 将下载的插件制品、回滚事务和快照保存在仅所有者可访问的本地状态中。Hub 不会透明缓存会话正文、工作区、终端输出、凭据或普通节点文件。

Node Agent 只安装公共 npm 制品大小受限、SHA-256 与操作者输入一致的精确语义插件版本。它记录依赖和 Cordis 文件，在不使用 Shell 的情况下调用 DSH Profile 管理，通过 `--dump-config` 验证 Profile 组合，验证已安装包 Manifest 与清单，并在应用失败时恢复已记录文件和冻结安装。快照清单描述显式的配置、依赖、数据或节点集合范围；疑似密钥文件与符号链接会被排除，每个归档都有哈希，恢复时根目录必须仍然匹配，带符号链接的父目录也不能将写入重定向到已配置根目录之外。

Hub Web UI 是经过审查的静态第一方应用。节点可以声明新的类型化能力，但接入节点绝不会让其提供的 JavaScript 在操作者浏览器中执行。新的富能力界面作为经过审查的 Hub 代码发布。

## Verification

协议测试覆盖签名、篡改、过期、协商、序号、去重、过时代次、持久重放和恢复。存储测试覆盖所有权、命令生命周期与脱敏、内容寻址、备份和审计链验证。服务端集成测试覆盖 Access 验证、Origin 检查、注册、已签名 Agent WSS 交换、命令路由、连接吊销、终端转发和审计读取。

Connector Composition 测试让本地 Web、桌面端和 Hub 调用方通过同一个模拟 `ApiProxy` 工作，并验证三类调用方使用同一个会话所有者。节点测试覆盖已认证本地 IPC、持久状态、快照排除与恢复隔离、乐观文件操作和真实 PTY 输出。发布检查会安装打包后的 Connector 与 Node Agent 制品，容器检查会为 Linux AMD64 构建 Hub 服务端和静态 UI。部署验收还会在 Hub 与 Connector 故障前后，让现有本地 Web 和桌面客户端使用同一个真实 DSH Runtime。

## Alternatives considered

**公开或反向代理每个节点的本地 Web 监听器。** 这会增加公开源站数量、让控制平面耦合浏览器传输，而且 Hub 无法提供本地 Web API 尚未包含的能力。

**在 Hub 内运行一个完整 DSH 实例。** 这会让控制平面成为带特权特殊模式的执行宿主，并且不能解决权威 Runtime 位于其他节点的会话访问问题。

**在本地 UI 旁运行第二个 Headless DSH 进程。** 即使两个 Runtime 所有者共享 Profile 目录，其内存状态仍可能分叉。把 Connector 加载到现有 Composition 中可以保留单一所有者，并让本地和远程客户端协作。

**把全部节点内容镜像到中心数据库或对象存储。** 这会引入不必要的第二事实源、扩大凭据和隐私边界，并要求任意的缓存保留与失效策略。

**执行节点提供的浏览器模块。** 这会把节点失陷扩散到操作者已经认证的控制平面源站。类型化能力描述和经过审查的第一方界面可以在不执行浏览器远程代码的情况下保留扩展性。

**要求每个节点交互式批准。** 这与单用户产品的完整权限合约冲突，也无法支持无人值守的节点集合管理。明确的边界是节点注册和 Node Agent 账户的操作系统权限。

## Consequences

该设计提供统一远程视图，同时让执行和权威数据保留在节点。本地 Web、桌面端和 Hub 可以继续同一实时会话，不需要复制数据库或运行第二个 DSH 进程。仅出站节点无需开放入站防火墙，持久化签名交付让断线可恢复。

Hub 与 Node Agent 仍然是安全敏感组件，因为注册会授予广泛权限。操作者必须保护 Hub 源站、Node Agent 账户、身份文件、Service Token、备份和制品批准流程。离线节点只会展示已索引元数据，直到重新连接；每项新能力或富 UI 功能都需要显式版本化适配器和经过审查的 Hub 界面。
