# DSH 上游兼容与节点升级

网关插件 `2.0.0-alpha.2` 当前明确验证 `0.1.7-rc.2` 与 `0.2.1-rc.2`，不把其他预发布版本视为兼容。邀请安装器与插件 peer 声明使用同一范围。新版客户端、Typert 描述和静态资源全部来自节点自己的 DSH 安装。Hub 不复制模型设置或凭据。

0.2.1 的原生 Connection 要求调用方 Peer。每条已配对插件连接创建独立的 owner Peer，HTTP 与 mux 共享它并允许原生交互；身份由本机受信插件创建，不读取浏览器提供的身份字段。Peer 随所属 Cordis 插件销毁。旧版没有 createPeer 时沿用原生旧接口。不同节点和不同 Hub 插件连接不能共享 Peer。

升级先保留节点 profile、会话和当前运行时，再在隔离目录安装精确版本。更新三个连接插件时保留命名 Loader 条目、工作区、授权和连接文件，停机切换前检查无活动任务。验证失败则切回旧运行时和原 profile。不要用重建默认 profile 的选项覆盖用户配置。

发布验证包括 check/build、不同节点 Peer 隔离、新旧原生 SDK、Chromium/WebKit 手机尺寸输入与 Full access、模型选择、测试消息和历史刷新、上传下载，以及实际三个连接包共存。运行时测试使用模拟模型。离线节点保留原身份，恢复连接后再升级，不能列入已完成。

0.2.1 上游不允许对已安装的第三方插件直接重复 install；须在原生 Plugins 页卸载再安装。控制版对此在创建作业前明确拒绝，不自行卸载，也不把未执行的更新报告为成功。连接、授权和 Gateway 核心插件继续禁止远程停用。
