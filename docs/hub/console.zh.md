# 使用 DSH Hub 控制台

[English](console.md) | 中文

本指南解释 Hub 在官方 DSH Web 基础上增加的功能。会话、项目分组、工作目录选择、消息流、工具展示、滚动和移动端交互均由官方 Web 提供。Hub 在官方新建会话行中增加一个节点／Runtime 选择器；管理入口位于左下角“设置”。

## 在指定节点和文件夹新建会话

1. 打开“新建会话”。主页面仍会汇总显示全部在线 Runtime 的项目分组与会话。
2. 在 Hero 行中选择“节点与 Runtime”；Hub 会预选上次仍可用的目标。
3. 使用旁边的官方 Workspace picker 选择已记录的文件夹，或浏览该节点的文件系统并添加一个。
4. 发送第一条消息。此后 Workspace 身份成为权威依据，所有请求会自动路由到其所有者。

在第一条消息前切换节点会清除之前的空白会话选择，避免消息误发到旧节点。选择 Fleet 列表中的已有 Workspace 时，节点选择器会自动同步到其所有者。整个流程不需要先进入设置页。

## 先看“当前 Runtime”，再修改设置

设置标题栏始终显示“当前 Runtime”。切换后不会重载整个页面；Hub 会同时刷新 Schema 设置和模型、权限、Agent 等直接 Host 控制器，并拒绝旧节点晚到的读取结果覆盖新值。

设置作用域如下：

| 页面／设置项 | 所有者 |
|---|---|
| 通用设置中的权限、默认 Agent、发送行为 | 当前 Runtime |
| 通用设置中的语言、外观 | 当前浏览器，与节点无关 |
| 模型、可配置插件、Agent 预设 | 当前 Runtime |
| Hub 节点 | Hub 全局 |
| 节点插件、更新历史、受管范围快照 | “节点插件”页内选择的管理目标 |

官方“插件”页配置 DSH 功能插件的运行参数；Hub 增加的“节点插件”页负责包版本盘点、更新和恢复，两者不是同一件事。

## 节点注册与兜底 Runtime

打开“设置 → Hub 节点”。

1. 输入便于识别的显示名称；节点 ID 会自动生成，也可在提交前修改。
2. 点击“生成注册码”。代码只显示一次并在 15 分钟后过期。
3. 为该节点创建独立的 Cloudflare Access Service Token。
4. 复制页面显示的一键安装命令并在目标机器运行。Client ID 只粘贴值本身，不要带 `CF-Access-Client-Id:` Header 名称；Client Secret 通过隐藏输入读取，不进入 Shell History。
5. “等待接入”显示尚未绑定的注册；可在过期前取消。“已登记节点”显示在线、离线、已吊销状态和每个 DSH Runtime。
6. “设为默认”只作为其他无所有者 Host 操作的兜底目标；新会话可直接在主页面选择节点。节点身份吊销会立即断开连接，但不会删除节点上的会话和文件。

一台物理机器只需一个 Node Agent，但可以接入多个拥有不同 Runtime ID 的 DSH Profile。每个节点必须使用不同的 Service Token。

如果注册报错称请求在抵达 Hub 前返回了非 JSON 页面，通常是 Cloudflare Access 或其他边缘层拦截了请求。请检查 Client ID 与 Secret 值、Access Application 是否具有接受该 Token 的 Service Auth Policy，以及该 Token 能否访问 `/hub/v1/bootstrap`；这些检查通过前不要反复更换注册码重试。

## 插件状态、更新与回退

打开“设置 → 节点插件”，先选择目标 Runtime。“当前插件”来自节点当下的 DSH Profile，不是 Hub 缓存：

- “运行正常”表示包已安装、位于 Profile Bundle 列表中，且安装版本与受管记录一致。
- “已停用”表示包存在但没有启用。
- “状态异常”表示包缺失或安装版本与受管记录不一致，应先检查节点日志，避免继续批量更新。

点击“检查更新”后，页面显示当前版与 Registry 最新版；只有确实存在新版本时才显示更新按钮。更新流程固定为：

- “外部管理”表示由本地文件、Workspace、Git 或独立 Release 安装；Hub 不查询 npm，也不会改写来源。
- “暂无法查询”只影响该插件；其他插件的状态与更新按钮仍可使用。
- “已是最新”表示 npm Registry 查询成功且版本一致。

1. 节点验证当前依赖锁没有在页面读取后发生变化。
2. 节点自动保存 Package Manifest、锁文件、Cordis 配置和受管插件记录，形成该次更新专属的回退点。
3. 节点从受限的公共 npm Registry 下载精确版本，记录制品哈希，调用 DSH Profile 管理并验证组合与安装结果。
4. 失败会立即自动恢复；成功会进入“更新与回退历史”，显示原版本、目标版本、时间和“一键回退到更新前”。

回退不会要求操作员记忆哈希、制品 ID 或快照 ID。如果之后又执行了更新，旧回退操作会因锁状态不匹配而停止，防止覆盖更新状态。

## 插件回退与受管范围快照的区别

插件更新不需要手工快照。插件回退点由每次更新自动创建，且只为撤销该次插件变更服务。

“受管范围快照与恢复”默认折叠，是独立的高级恢复功能。它不是磁盘或操作系统整机镜像：

- 配置：顶层 Cordis 组合文件。
- 依赖：Package Manifest 与锁文件。
- 数据：Node Agent 配置中明确批准的 `snapshotPaths`。
- 全部受管路径：过滤后的 Profile 配置、依赖和获准数据范围。

快照存在节点的 Node Agent 私有状态目录，不上传或缓存到 Hub。恢复前节点还会自动建立保护快照。名称类似机密的文件、环境文件和符号链接会排除，但系统不会检查任意文件内容是否包含机密。

## 终端和文件为什么存在

“设置 → Hub 节点 → 高级诊断：终端与文件”默认折叠。这两项是普通 DSH 工作流失效时的救援通道，不是主导航功能。

- 应急终端：用于检查或重启 Node Agent、Connector、DSH Profile 与系统服务。打开前必须确认风险；PTY 随页面关闭，不保存为会话，浏览器只保留有限 Scrollback。
- 按路径检查文件：用于读取已知日志或修复已知配置。操作必须从节点绝对路径开始，不建立全盘索引。只有完整读取且不超过 1 MiB 的 UTF-8 文件可以编辑；保存和删除会携带读取时的内容版本，如果节点文件已经改变则拒绝操作。二进制和大文件只读。

两者都以 Node Agent 的操作系统账户执行，并进入 Hub 审计。Node Agent 用 Root 或管理员账户运行时，Hub 就拥有同等权限。

## Hub 保存什么

Hub 只用 SQLite 保存节点身份、Runtime 与能力基线、最小会话发现字段、可靠投递状态、短期命令正文和审计链。操作完成并被浏览器领取后，敏感命令正文会清除。

Hub 不缓存完整会话、工作区文件、终端输出、插件制品、插件回退事务或快照。它们由节点保存并在需要时读取，因此 Hub 备份与 Node Agent 状态备份是两个独立边界。
