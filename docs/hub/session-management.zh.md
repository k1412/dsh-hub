# 归档、回收站与永久删除

[English](session-management.md) | 中文

打开 **设置 → 会话管理**。页面默认汇总所有支持此功能的在线节点，也可以选择某个节点／Runtime，再按标题、项目路径或会话 ID 搜索。每条会话始终标明所属节点，操作会回到该节点执行。

| 操作 | 结果 | 如何撤销 |
| --- | --- | --- |
| 归档 | 从普通侧栏隐藏，历史仍保留 | 在“已归档”中选择“取消归档” |
| 删除 | 进入所属节点的回收站，从普通列表和 Hub 发现索引移除 | 在“回收站”中选择“恢复” |
| 永久删除 | 删除该会话的源日志及历史格式代际，清理工作区关联 | 无法撤销，需要单独确认 |

这些操作只管理会话记录。项目目录、用户文件和其他会话都保留。回收站不会按时间自动清空；节点重新启动后仍能查看和恢复。恢复时保留删除前的状态：原来正常的会话恢复到正常列表，原来已归档的会话恢复到“已归档”。

## 日常操作

1. 在“正常”中找到会话，选择“归档”或“删除”。运行中的会话需要先停止任务；后台任务或定时任务仍活跃时，节点也会拒绝删除。
2. 在“已归档”中查看以前隐藏的会话，选择“取消归档”即可重新显示。
3. 在“回收站”中恢复误删的会话。确认不再需要时，点击“永久删除”，核对会话标题和节点，勾选确认后提交。

删除到回收站后，旧 Hub 会话地址和发送请求都会被节点拒绝；恢复后可继续使用。页面会刷新列表和侧栏。节点离线时无法修改源记录；列表会明确列出离线或需要升级的节点，不会把读取失败当成空列表。

## 日志仍被打开时

原版 DSH 尚未提供单会话卸载接口。即使任务已完成，Runtime 仍可能持有这条会话日志的写入锁。因此，进入回收站可以立即完成，永久删除只在会话未被 Runtime 打开且取得独占日志锁后执行。

如果回收站提示日志仍被打开，请结束该节点的任务并重启对应 Runtime，再回来执行永久删除。关闭浏览器标签页不保证写入锁释放。Hub 不会为删除一个会话而自动中断节点上的其他任务。

永久删除会清理该 Runtime 持久化目录中目标会话的所有日志代际。节点以写入锁保护清理，保留无正文的锁文件，避免删除锁 inode 后出现并发写入。删除中断时，节点根据持久化日志继续完成清理；已经开始永久删除的记录不会再提供恢复。

已导出的会话副本或独立备份不在这次删除范围内，需要分别管理。

## 支持范围

此功能通过独立的 `dsh.session-lifecycle` 能力协商提供，需要更新后的 Hub、Node Agent 和 Connector，并使用当前已验证的 DSH `0.1.7-rc.2` JSONL 持久化后端。旧节点仍可继续原有会话操作，但会显示需要升级。旧格式日志须先在 DSH 中打开，完成格式迁移，再归档删除。

回收站元数据位于节点本地、按 Runtime 隔离，并以仅所有者可读写的文件保存。Hub 只保存最小发现索引和操作审计，不接管原会话存储。[清理离线节点的 Hub 缓存](console.zh.md)与会话删除是两个独立操作。
