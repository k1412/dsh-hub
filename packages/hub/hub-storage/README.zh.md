# dsh-hub-storage

[English](README.md) | 中文

`@k1412/dsh-hub-storage` 提供单 Hub 的 SQLite 持久化边界。数据库仅允许所有者访问，启用外键、WAL 日志、完全同步持久化和严格表，禁用扩展加载，并要求 Schema 版本精确匹配。

## 存储的数据

控制数据库保存已注册节点身份、吊销状态、连接代次、可靠投递 Journal、Runtime 能力基线、最小会话发现索引、持久命令状态和哈希链审计日志。SQLite 触发器从数据库层保证审计记录只能追加。

命令意图在网络投递前持久化。合法状态转换明确区分待处理、已发送、运行中、成功、失败和结果未知。浏览器显式确认终止结果后，Hub 会删除已完成命令的请求与结果内容，并定期清理超过有界保留窗口且无人领取的已完成正文，同时保留哈希与生命周期元数据。

SQLite Trigger 保证审计记录只能追加，验证哈希链时可以发现记录变化或顺序重排。该哈希链不是签名或外部透明日志，不能抵抗有权替换数据库并重新计算全部哈希的管理员。

Hub 不设置文件缓存或对象目录。对话正文、工作区文件、附件、终端输出、原始日志、插件制品、插件回退事务、快照和凭据始终以节点为权威来源，本存储包不会镜像这些内容。会话发现只保存标识符、标题、工作目录、时间戳、运行状态和过期状态。

## 备份边界

Runtime 的完整发现基线会替换旧索引，并移除新基线中已不存在的会话。临时断线保留最后一次基线并标记过期；吊销节点会移除该节点的发现缓存，并停止把其 Runtime 加入工作区聚合，同时保留节点身份与审计历史。Hub 节点设置中的“清理 Hub 缓存”可移除离线节点的会话和工作区列表缓存，节点原始会话仍然保留，重新上线后会再次同步。节点端的归档和删除仍要求 Runtime 可连接。

对于旧版本遗留的缓存，备份后可在 Hub 主机运行 `node /app/hub-server.mjs clear-revoked-discovery`。此本地管理命令只清理已吊销节点，并写入审计记录。

`HubControlStore.backupTo()` 使用 SQLite 在线备份创建事务一致的数据库副本。运维备份只需保存 `hub.db` 和校验 Manifest；节点上的插件回退事务和快照属于另一套故障域，应随节点状态单独备份。

## 模型体验

无。本包只负责控制面持久化，不注册任何面向模型的能力。

#### KV Cache 影响

无；持久化的控制记录不会进入模型请求。

## 已知限制与后续工作

- 当前 Schema 版本为 3；改变版本的升级必须执行对应 Release 的备份和迁移流程。
- 推荐拓扑只运行一个活动 Hub 写入者。高可用多写存储需要独立的一致性设计，不使用网络挂载的 SQLite 模拟。
