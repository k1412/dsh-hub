# dsh-hub-server

English | [中文](README.zh.md)

`@k1412/dsh-hub-server` assembles the single-user Hub control plane. It provides the authenticated browser API, official Web HTTP/event routing, live SSE fan-out, static UI delivery, outbound Node Agent WebSocket termination, node enrollment, capability command delivery, and audit publication. It never loads DSH, an LLM provider, a node plugin, or an execution backend.

Every origin request first passes an application-layer private-origin secret. Human routes then verify a Cloudflare Access application JWT and an exact operator email allowlist. Agent routes verify a Service Token `common_name`, bind it to one enrolled node, and complete an Ed25519 challenge-response before accepting capability traffic. The server validates issuer, audience, time claims, token type, key rotation, signed node envelopes, boot identity, and connection generation.

Browser mutations require the configured HTTPS `Origin`, JSON content type, and same-origin Fetch Metadata when present. No CORS permission is emitted. Security headers disable framing, cross-origin opener sharing, MIME sniffing, referrer leakage, inline scripts, dynamic evaluation, and response caching. The style policy permits the inline style attributes and `<style>` elements generated by the reviewed official client bundles; scripts remain limited to same-origin static assets. The Hub boot script selects Zod's non-JIT parser before the official entry runs, and Loader compiles its expression evaluator only when a composition contains an expression node.

The static directory is a fixed build of official DSH Web with the reviewed Hub Settings plugin; nodes cannot upload frontend code. Fleet list/search requests aggregate every online Web-capable runtime. A minimal session index for an offline runtime remains grouped by working directory and explicitly labeled offline, while history and chat operations wait for its owner to reconnect. Opaque browser identities route later official `/api/*` calls to the owning runtime, while event WebSockets multiplex all online runtimes; a selected default runtime applies only to operations without an existing identity. SSE transfers control-plane node events without retaining their payloads. SQLite persists command intent and delivery state; completed bodies remain only until explicit browser acknowledgement or bounded periodic cleanup, so Hub does not become a transcript or workspace replica.

The node list combines the Node Agent's upstream outbox report with Hub's downstream outbox state, including records, bytes, oldest record, capacity, last heartbeat, pressure, and suppressed streams. Pressure changes enter the audit log. An affected official event connection closes and resynchronizes so the browser does not continue from an incomplete stream.

## Model Experience

None, as this server is an operator control plane and registers nothing model-facing.

#### KV Cache effect

None; Hub transport and API records do not enter a model request.

## Known Limitations and Deferred Work

- The package expects one active Hub server process for its SQLite database and event fan-out.
- TLS and Cloudflare Access policy enforcement occur before the origin. The application still validates every Access JWT because a private reverse proxy is not an identity proof.
